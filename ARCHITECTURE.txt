## 🔧 Backend Architecture (`smart-bus-backend/`)

```
smart-bus-backend/
├── server.js                   # Main Express server entry point
├── package.json                # Dependencies: express, mysql2, bcrypt, jwt, cors, etc.
├── .env                        # Environment variables (DB credentials, JWT secret)
│
├── config/
│   └── db.js                   # MariaDB/MySQL connection pool configuration
│
├── controllers/                # Business logic handlers
│   ├── authController.js       # Login, register, /auth/me
│   ├── adminController.js      # User search, CRUD, reports (admin/operator)
│   ├── cardController.js       # Card CRUD, recharge, payment operations
│   ├── operatorController.js   # Operator-specific logic (user search, stats)
│   ├── controllerController.js # Controller validation logs, stats
│   ├── manualPaymentController.js # Manual payment verification workflow
│   └── tripController.js       # Trip/ticket booking (guest users)
│
├── models/                     # Database access layer (SQL queries)
│   ├── userModel.js            # User CRUD: create, getAll, findByEmail, getById
│   ├── cardModel.js            # Card operations: create, getByUserId, recharge, pay
│   ├── transactionModel.js     # Transaction history
│   ├── ticketValidationModel.js # Controller validation records
│   ├── controllerLogModel.js   # Controller activity logs
│   ├── manualPaymentModel.js   # Manual payment records
│   └── tripModel.js            # Trip/ticket data
│
├── routes/                     # API endpoint definitions
│   ├── authRoutes.js           # POST /auth/login, /auth/register, GET /auth/me
│   ├── adminRoutes.js          # GET /api/users, /api/users/search, DELETE /api/users/:id
│   ├── cardRoutes.js           # /api/cards/* (CRUD, recharge, payment)
│   ├── operatorRoutes.js       # /api/operator/* (dashboard, user management)
│   ├── controllerRoutes.js     # /api/controller/* (validation, logs)
│   ├── manualPaymentRoutes.js  # /api/manual-payments/* (verification)
│   ├── tripRoutes.js           # /api/trips, /api/tickets (guest booking)
│   └── esp32Routes.js          # /api/rfid/* (ESP32 card scanning)
│
├── middleware/
│   ├── auth.js                 # JWT verification + role-based access control
│   └── errorHandler.js         # Centralized error handling
│
├── services/
│   └── esp32SerialService.js   # Serial port communication with ESP32 RFID reader
│
├── scripts/                    # Database migrations/utilities
│   ├── apply-002-enforce-card-user.js
│   └── reassign-orphan-cards.js
│
├── tests/
│   └── api.test.js             # Jest API tests
│
└── sql.sql                     # Database schema (CREATE TABLE statements)
```

### 🔑 Key Backend Features
- **Authentication**: JWT-based with 4 roles: `admin`, `operator`, `user`, `controller`
- **Database**: MariaDB with 9 tables (users, cards, transactions, validations, payments, trips, etc.)
- **Role-based Access**: `requireAuth(['admin', 'operator'])` middleware
- **ESP32 Integration**: Serial port service for RFID card scanning
- **API Structure**: RESTful endpoints grouped by domain (auth, cards, payments, etc.)

### 🎯 Frontend Features
- **Role-based Routing**: Different dashboards for admin/operator/controller/user
- **Glassmorphism UI**: Modern design with `backdrop-blur`, gradients, semi-transparent panels
- **Authentication Flow**: Login → fetch user role → redirect to appropriate dashboard
- **State Management**: React hooks (useState, useEffect, useCallback)
- **API Integration**: Centralized `apiClient.js` for all backend calls
- **Responsive Design**: TailwindCSS with mobile-first approach

## 🔐 User Roles & Access

| Role | Dashboard Route | Capabilities |
|------|----------------|--------------|
| **Admin** | `/AdminDashboard` | All operator features + user type stats + staff activity monitoring + system reports |
| **Operator** | `/operator` | User management, payment verification, dashboard stats |
| **Controller** | `/controller` | Ticket validation, validation history, controller stats |
| **User** | `/client` | Card management, manual payments, transaction history |
| **Guest** | `/booking` | Book tickets with RFID card payment (no login) |

## 🗄️ Database Schema (9 Tables)

```sql
1. users              # All system users (admin/operator/user/controller)
2. cards              # RFID cards linked to users
3. transactions       # Card recharge/payment history
4. ticket_validations # Controller validation records
5. controller_logs    # Controller activity logs (login/logout/breaks)
6. manual_payments    # Manual payment requests (pending/verified/rejected)
7. trips              # Bus trip definitions (routes, times, prices)
8. tickets            # Guest ticket bookings
```

## 🔄 Request Flow Example

### Login Flow
```
1. User → POST /auth/login (email, password)
2. Backend → Validates credentials → Returns JWT token
3. Frontend → Stores token in localStorage
4. Frontend → GET /auth/me (with token) → Gets user role
5. Frontend → Redirects based on role:
   - admin → /AdminDashboard
   - operator → /operator
   - controller → /controller
   - user → /client
```

### Card Recharge Flow (Operator)
```
1. Operator → POST /api/cards/recharge (uid, amount) + JWT token
2. Backend → requireAuth(['operator', 'admin']) → Verifies token
3. Backend → Updates card balance → Creates transaction record
4. Backend → Returns updated card data
5. Frontend → Displays success message
```

## 📊 API Endpoints Summary

### Authentication
- `POST /auth/login` - User login
- `POST /auth/register` - User registration (role=user)
- `GET /auth/me` - Get current user info

### Admin/Operator
- `GET /api/users` - List all users
- `GET /api/users/search?q=&role=` - Search users by role
- `POST /api/users` - Create user (any role)
- `DELETE /api/users/:id` - Delete user

### Cards
- `GET /api/cards` - List all cards (admin/operator)
- `GET /api/cards/my-cards` - User's cards
- `POST /api/cards/recharge` - Recharge card (operator)
- `POST /api/cards/me/recharge` - User recharge own card
- `POST /api/cards/pay` - Pay fare (operator)

### Manual Payments
- `GET /api/manual-payments/all` - All payments (operator)
- `GET /api/manual-payments/pending` - Pending payments
- `PATCH /api/manual-payments/:id/verify` - Approve/reject

### Controller
- `GET /api/controller/all-validations` - All validations
- `GET /api/controller/all-logs` - Controller activity logs
- `POST /api/controller/validate` - Validate ticket

### Trips (Guest Booking)
- `GET /api/trips` - Available trips
- `POST /api/tickets` - Book ticket with card payment

This architecture supports a complete bus ticketing system with RFID card payments, role-based access control, and real-time validation capabilities.
